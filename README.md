# AgenticRL · 多步工具调用的 SFT 与 GRPO

**让小参数模型从“会调用工具”走向“正确完成多步任务”。**

AgenticRL 是基于 **Qwen2.5-0.5B-Instruct** 的工具使用 Agent 训练与评测项目，打通了**场景构建、确定性工具执行、LoRA SFT、答案主导 GRPO、多种子训练、冻结评测与统计复算**的完整流程。

在固定模型和评测协议后的 **240 个合成测试场景**上，三个 GRPO 训练种子的答案正确率均高于同一 SFT30 基线：平均正确率从 **60.00% 提升至 72.50%**，增加 **12.50 个百分点**；最高种子达到 **75.42%**。

## 最终实验结果

四个模型使用相同的确定性工具、答案判定器与 greedy 推理协议。SFT30 为共同基线，三个 GRPO 模型分别使用 seed 20261011、20261012、20261013。

| 模型 | 答案正确 | 正确率 | strict 参考链完整 | semantic 路线有效 | 动态依赖有效 | 平均工具调用 |
|---|---:|---:|---:|---:|---:|---:|
| SFT30 | 144/240 | 60.00% | 147/240 | 151/240 | 60/144 | 1.692 |
| GRPO seed11 | 181/240 | 75.42% | 189/240 | 193/240 | 102/144 | 1.871 |
| GRPO seed12 | 171/240 | 71.25% | 176/240 | 179/240 | 90/144 | 1.821 |
| GRPO seed13 | 170/240 | 70.83% | 175/240 | 180/240 | 88/144 | 1.808 |

- **三个 GRPO 种子的平均正确率：72.50%，样本标准差 2.53 个百分点。**
- **相对 SFT 的平均增量：+12.50 个百分点。**
- **任务配对 bootstrap 95% 区间：[8.33, 16.67] 个百分点**，按 240 个同题差值（三种子平均 − SFT）重采样。
- 三个种子分别比基线净增加 **37 / 27 / 26** 道正确任务。

### 代表性任务成果

- **密度计算与单位转换**：查询人口和面积、计算密度后，继续完成 km² 到 mile² 的换算，三个 GRPO 模型均完成对应案例的三步参考链与正确回答。

## 技术方案

### 1. 确定性工具环境与分层场景

项目提供计算器、天气、搜索、单位转换和国家数据查询五类本地工具。模型通过工具 schema 生成动作，执行器返回 observation，模型据此继续调用或生成最终答案。

数据集固定为 **train 1200 / validation 180 / test 240**，支持单步调用、多步串联、前一步结果驱动的动态参数，以及 IID、参数、表达、组合四类评测分层。数据构建包含结构校验、分组泄漏检查与参考执行核验。

### 2. LoRA SFT 建立工具使用基线

从 train 场景构建专家工具轨迹，使用 **assistant-only 监督**学习工具选择、参数生成、多轮交互与最终回答，工具 observation 作为上下文输入。训练过程支持 checkpoint 保存与继续训练，并使用完整 validation 按答案正确数、动态依赖有效数、较早训练步依次选点，得到 SFT30 基线。

### 3. 答案主导的可验证奖励

将最终任务正确性作为主奖励，流程表现作为有界辅助信号：

```text
A = 完整结束且最终答案数值、单位、协议正确 ? 1 : 0
F = clip((流程分 + 3) / 7, 0, 1)
R = A + 0.2 × F
```

正确答案奖励为 **[1, 1.2]**，错误答案奖励为 **[0, 0.2]**。该设计在奖励排序上优先保证任务成功，同时保留流程反馈；合法替代路线获得正确答案时，同样可以取得答案主奖励。

### 4. 三种子独立 GRPO 训练

三个 seed 均从同一 SFT30 checkpoint 和全新 AdamW 开始，使用相同的问题顺序、独立的采样随机性。

| 配置 | 设置 |
|---|---|
| 计划批次 | 每 seed 60 批，每批 2 个场景 |
| 组内采样 | 每场景 4 条 rollout |
| 策略更新 | 原生 PyTorch GRPO，clip 0.2，学习率 `5e-6`，beta 0 |
| 优势计算 | 组内相对奖励，按样本标准差加 `1e-4` 归一化 |
| 损失范围 | 多轮 assistant-only 动作 mask |
| 验证选点 | 计划批次 20 / 40 / 60，各评完整 180 个 validation 场景 |
| 实际有效更新 | 三个 seed 分别为 28 / 31 / 31 次，零信号批次跳过更新 |

### 5. 冻结评测与结果复核

在 test 前固定四个模型身份、数据、判定器、解码方式和统计规则。逐题记录原始响应、工具事件、checker 结果、token 数、耗时与 CUDA 内存指标，并执行原子保存、备份读回和哈希核对。

评测区分**最终答案、strict 参考链、semantic 路线、动态依赖**，按场景深度和泛化类型分层，再对同题结果进行配对统计。最终评测在 **A100-SXM4-40GB** 上使用 **BF16 / eager / greedy** 完成，进程总耗时约 **1 小时 26 分钟**，960 条任务记录均完成，基础设施失败计数为 0。

## 完整流程

```text
场景生成与审计 → 冻结数据、工具与配置
                         ↓
              专家轨迹 → LoRA SFT → SFT30
                         ↓
              三个独立 seed 的 GRPO
                         ↓
任务 + 工具 schema → 模型动作 → 工具执行 → observation
                         ↑                         │
                         └──── 下一轮交互 ──────────┘
                         ↓
                最终答案 + 流程判定
                  ├─ train：奖励 → 组内优势 → 策略更新
                  ├─ validation：固定规则选择 checkpoint
                  └─ test：四模型同题评测 → 重放核验 → 配对统计
```

最终训练栈为 **Python / PyTorch / Transformers / PEFT / LoRA**。代码覆盖数据构建、工具交互、监督训练、策略优化、评测执行与结果分析各层。
